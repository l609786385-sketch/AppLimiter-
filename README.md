# AppLimiter · 应用时间管家

面向 Windows 10/11 的本地桌面应用限时 MVP，使用 Python、PySide6、psutil、Windows API 和 SQLite。后台监测与主窗口是两个独立进程，所有规则和使用记录都保存在本机，不需要服务器、云数据库或付费 API。

**交付状态：源码已实现；尚未在 Windows 实机验证，也没有附带已验证的 Windows EXE。** 当前测试环境是 Linux。跨平台核心、模拟的安全边界、Qt 数据联动和后台数据库集成测试通过，不代表 Windows 原生功能已经通过。具体结果见 `TEST_REPORT.md`。

## 已实现的功能

- 从正在运行且有窗口的应用列表、或文件选择器添加 EXE。
- 多应用独立管理，每个应用设置单次、每日累计上限，默认 30 / 60 分钟。
- 默认仅前台计时；切到后台、锁屏、休眠不计入已观测的使用时长。
- 单次耗尽结束已匹配进程；所有匹配进程退出后新启动开始新的一次，保留当天累计。
- 每日累计耗尽后结束目标，并每 0.5 秒检查再次启动；无需再次成为前台即可拦截。
- 按 Windows 当前本地日期切换每日额度；午夜前后的采样区间分别归入两天。
- SQLite 持久化每日用量和活动会话，主窗口关闭、监测重启、重新登录或电脑重启均不会主动清除当天记录。
- 暂停、启用、编辑、删除规则；删除规则保留历史记录。
- 中文可调整大小的窗口，主页用量、剩余时间、进度与状态，每日记录、监测日志。
- 独立后台托盘、收起/最小化至托盘、托盘重新打开主窗口、登录自启动。
- 单次和每日额度剩余 5 分钟、1 分钟时提醒，提醒事件也保存在日志中。

以上 Windows 原生行为仍需要按下文在 Windows 验证。强制结束可能丢失目标应用未保存的数据，添加规则的窗口中也会提示。

## Windows 运行

建议 Windows 10/11 x64、Python **3.12 x64**，从 python.org 安装并启用 Python Launcher。项目安装依赖时需要联网，安装后软件本身可离线运行。

解压完整项目，然后在项目根目录打开 PowerShell：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

也可以双击 `scripts\run_windows.bat`。该脚本会安装依赖并使用 pythonw 启动界面。源码模式下不要删除或移动项目与虚拟环境，否则登录自启动路径会失效；移动后取消并重新勾选自启动。

单独启动后台（无需打开主窗口）：

```powershell
.\.venv\Scripts\python.exe main.py --worker
```

首次运行不自动修改自启动设置。在窗口中勾选“登录 Windows 后自动启动后台监测”，会写入当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\AppLimiter`，不需要系统级服务或管理员安装。

## 使用方法与计时语义

1. 点击“添加应用”，选择 EXE，或从运行列表选择应用。
2. 设置显示名称、单次和每日上限，然后保存。
3. 主页显示累计及本次用量。切到其他应用后，两个计时器都暂停，不因切后台而清除本次用量。
4. 编辑限制不会清除已经使用的时间。将限制调小至低于已用时长，下一轮检查会执行关闭。
5. 暂停规则会暂停计时和拦截，已保存的用量继续保留；启用后恢复执行。
6. 关闭主窗口后后台继续运行；最小化或“收起到托盘”会隐藏窗口，双击蓝色时钟托盘图标可重新打开。
7. 在后台托盘选择“退出后台监测”会明确停止监测。MVP 允许用户这样退出，自启动设置不会因此被删除。

“单次”指当前这一组匹配进程存活期间累计的前台时长。离开前台只暂停；直到全部已配置进程结束才开始新的一次。如果主程序退出而已配置的辅助进程仍在运行，本次用量会保留。

每条规则可添加多个**明确选择的完整 EXE 路径**，包含一个应用的主程序及辅助程序。相同 EXE 的多个实例自动归到同一条规则；配置多个 EXE 也只对当前前台进程计时一次。路径大小写和 `..` 会规范化，同一个路径不能同时归入多条规则。

不按文件名、不按目录通配、不任意结束子进程。不同路径的同名 EXE 不会被规则匹配。安装器/启动器与实际播放窗口若是不同 EXE，建议从实际播放窗口的运行列表添加，并按需要明确添加辅助 EXE。更换安装路径后需要编辑规则。

软件不会结束 Windows 目录内的程序、AppLimiter 自身、源码运行时的同目录 Python/Pythonw、系统关键进程，以及不属于当前用户登录会话的进程。结束前会再次核对当前规则、EXE 路径与创建时间，Windows 核对与结束使用同一个进程句柄。

## 数据保存与边界

默认数据目录：

```text
%LOCALAPPDATA%\AppLimiter\
  applimiter.db           规则、路径、每日用量、活动会话、事件和后台状态
  applimiter.db-wal/shm   SQLite 运行文件（存在时不要单独删除）
  worker.log             后台异常日志，2 MB × 4 份轮转
  gui.log                主窗口异常日志
  window.ini             窗口尺寸和位置
  worker.lock/gui.lock    进程单实例锁
```

每天切换日期时读取对应日期的记录，不会删除上一天历史，因此跨午夜时不用主窗口开着，也不用为了重置额度启动一个额外的定时任务。软件在午夜关闭、次日再启动也会正确读取新一天；回到曾经记录的日期时会读回该日期的用量。

每次有效采样先用 SQLite 事务保存用量、会话和状态，再执行关闭。`WAL + synchronous=FULL` 保证正常 SQLite 事务持久性；突然崩溃可能丢失尚未采样的约 0.5 秒，未观察到的离线时间不会补计。

计时使用单调时钟，日期使用 Windows 本地时间。采样间隔大于 2.5 秒、时钟突跳或前台进程在区间两端发生变化时，该不确定区间不计入用量。前后台切换通常有不超过一个采样间隔的误差；在采样间隔内极快切换，或后台被冻结，可能漏计。休眠期间不补算。本版不提供防系统时间篡改。

限额后的启动拦截是启动**后**轮询并结束，通常约 0.5 秒加进程扫描耗时；不是内核级“禁止创建进程”。目标短暂出现窗口属此 MVP 的边界。普通权限无法结束提升权限/受保护进程时，会记录异常并重试，不退还已经消耗的额度，也不扩大关闭范围。需要与目标相同权限时，请仅在确有需要的情况下用相同权限运行 AppLimiter。

后台仅在用户登录后运行，不是 Windows 系统服务。自启动被禁用、后台主动退出/被结束、用户未登录、系统关闭期间都不会计时或拦截，已有数据库记录仍保留。多条访问受限的目标使采样不完整时会保守暂停该区间计时，以免误计。

## 自动化测试

核心、界面数据联动、后台事务与模拟安全边界测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

普通执行会明确跳过 Windows 原生测试。Linux 可安装相同依赖并运行此命令，Qt 集成测试使用 offscreen，操作系统相关调用使用 mock，不能据此宣称 Windows 验证通过。

**Windows 原生验证须在已解锁的本地交互桌面执行：**

```powershell
.\.venv\Scripts\python.exe scripts\verify_windows.py
```

验证脚本会：

- 使用 Windows 自带 .NET Framework 的 `csc.exe` 编译 `scripts\TestApp.cs`，创建独立临时测试 EXE。
- 实测前台识别、匹配进程查询、同句柄终止、伪造创建时间和不匹配规则的拒绝行为。
- 在专用临时数据目录启动后台，实测前台计时、每日超限关闭、再次启动拦截、后台重启后的拦截和持久化。
- 实测主窗口启动，并检查它启动的独立后台心跳。
- 运行其余全部测试，有失败或跳过则拒绝生成验证凭据。

不修改正常 AppLimiter 数据、自启动设置或真实应用的规则。测试会关闭它自己创建的临时进程。若 Windows 阻止自动把测试窗口切到前台，点击标题为 `AppLimiter disposable test target` 的临时窗口并重试；未满足前台验证会失败，不会标为通过。远程非交互会话、锁屏、缺少 .NET Framework 编译器均不能完成本验证。

## 生成 Windows EXE

仅在 Windows 上构建，PyInstaller 不能在 Linux 交叉生成 Windows EXE。本交付未运行以下 Windows 构建命令。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1
```

脚本会创建虚拟环境、安装 `requirements-build.txt`、**重新运行完整 Windows 验证**、执行 PyInstaller，然后再用相同测试验证打包后的后台和窗口。任一步失败或跳过都会返回失败，不会把 ZIP 作为成功交付。

成功后的文件：

```text
dist\AppLimiter\AppLimiter.exe
dist\AppLimiter\_internal\...          必需的运行时文件
dist\AppLimiter-Windows-x64.zip          完整可分发目录
.windows-verification.json              源码原生验证凭据
.windows-package-verification.json      打包程序验证凭据
```

采用 PyInstaller **onedir** 包：无需目标机器安装 Python，但必须保留整个 `AppLimiter` 文件夹，不能只复制 EXE。这是独立桌面软件的目录包，不是安装器。未做代码签名，首次下载运行可能出现 Windows SmartScreen 提示。

## Windows 手工验收清单（尚未完成）

自动化脚本覆盖核心原生路径，但不会验证 Windows 通知设置、真实登录、重启或用户安装的播放器。发布前应分别在 Windows 10/11 完成：

| 操作 | 预期 |
| --- | --- |
| 用运行列表和 EXE 两种方式添加专用测试应用 | 路径正确，规则保存，重复路径不会新增规则 |
| 两个应用交替前台，各有多个实例 | 只累计前台所属规则；同应用多个实例不翻倍 |
| 单次设 1 分钟、每日设 3 分钟 | 单次耗尽关闭；重开能用下一次，当天累计保留 |
| 用完每日额度后反复重开，或后台启动目标 | 每次均再次被结束，当天额度保留 |
| 切换后台、锁屏、休眠再恢复 | 对未观测的后台/锁屏/休眠区间不计时 |
| 跨本地午夜持续使用 | 两天记录分别保存，每日恢复，本次计时保留 |
| 已用一部分后退出主窗口、后台重启、注销、重启电脑 | 今天的记录保留，开启自启动后登录恢复监测 |
| 主窗口最小化、关闭，双击托盘重新打开 | 后台继续；界面恢复且不会产生双份后台 |
| 调整窗口、切换 Windows DPI 100%/150%/200% | 布局可用，表格可滚动，窗口尺寸记住 |
| 用限额大于 5 分钟的测试程序经过 5 分钟和 1 分钟阈值 | 托盘提醒出现，日志各有记录；检查 Windows 通知设置 |
| 启用/暂停/删除/编辑限额 | 动作生效，历史用量不因编辑、暂停或删除而擦除 |
| 提权目标、卸载目标、路径变化、数据库只读/损坏 | 显示/记录异常，不误关其他程序，不自动重建并清空额度 |
| 勾选/取消自启动并重新登录 | 当前用户启动项生效，取消后不自动启动 |
| 解压分发 ZIP 到另一台无 Python 的 Windows x64 电脑 | 整个目录包能够运行；再次完成核心验收 |

需要备份时先从托盘退出后台、关闭主窗口，再复制整个数据目录。卸载本 MVP 是取消自启动、退出后台并删除程序目录；数据目录可保留。

## 项目结构

```text
main.py                     源码及 PyInstaller 入口
applimiter/
  model.py                  规则、进程身份与采样模型
  storage.py                SQLite 事务、历史和会话存储
  engine.py                 可注入时间与采样的计时核心
  windows.py                前台/桌面/进程查询与安全结束适配器
  worker.py                 独立后台、轮询、托盘、提醒
  gui.py                    中文主页、规则编辑、历史和日志
  runtime.py                子进程启动、数据目录、当前用户自启动
  appearance.py             界面样式、时钟图标
tests/                      核心、Qt、模拟安全边界、后台、原生测试
scripts/                    Windows 运行、验证、打包与专用测试目标
AppLimiter.spec             PyInstaller 目录包配置
requirements*.txt           运行/构建依赖
TEST_REPORT.md              本次真实验证范围
```

## 后续版本

本版遵循自愿使用的本地限时工具定位。没有密码锁、规则防修改、进程防退出、管理员策略、服务看护、防更改系统时间、防删除数据库或改名/复制 EXE 的机制。规则暂停、删除或退出是可用的正常功能。密码及防绕过机制应在 Windows 实机验收 MVP 后单独设计和测试。
